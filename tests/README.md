# tests —— 本地字幕工具自检

这个目录放着两套回归测试。**改完代码建议跑一遍**，尤其是改 `ui/index.html` 之后。

## 怎么跑

- **双击** `run_tests.bat`（会自动找 Python，中文不会乱码）
- 或者命令行：`python tests/run_all.py`

输出末尾会有一行汇总，全过就是 `结果：全部通过`。

## 两套测试分别管什么

| 测试 | 文件 | 干什么 |
|---|---|---|
| 启动脚本静态检查 | `bat_lint.py` | 检查 `启动.bat` 的编码、行尾、括号平衡、路径斜杠、关键逻辑是否完整 |
| 界面冒烟测试 | `ui_smoke.js` | 在 Node 里用 DOM 桩加载 `ui/index.html` 的脚本，把真实交互路径跑一遍（81 项断言） |
| 变异测试 | `mutation_check.py` | 故意改坏源文件，验证上面两套测试**真的会报错**（不参与默认自检） |

### 为什么不直接双击 `启动.bat` 试试

因为**当前开发环境不允许调用 `cmd.exe`**（Bash 和 PowerShell 两个入口都会被安全策略拦截）。
`.bat` 没法执行验证，所以退而求其次，把「能静态查出问题」的部分全部自动化 —— 这就是 `bat_lint.py`。

真正的可用性验证，还得靠你自己双击一次 `启动.bat`。

### 界面冒烟测试为什么值得存在

`node --check` 只验语法，验不出这些：

- 函数名写错 / 调用了未定义的函数
- `$('xxx')` 引用了 HTML 里**不存在**的 id
- 状态没重置（比如移除文件后 `input.value` 没清空，导致再选同一个文件界面没反应）
- 提示文本被轮询覆盖、进度条卡在错误的值

`ui_smoke.js` 的 DOM 桩会**拦住不存在的 id**（直接抛错），并且真的去调
`boot` / `pickFile` / `startJob` / `render` 这些函数，所以上面这些问题都能被抓住。

## 测试自己的有效性（变异测试）

「一个不会失败的测试等于没有测试」。这两套测试都用**变异测试**验证过：
故意把源文件改坏（去掉修复、改错斜杠、混入裸换行、写单百分号……），
确认测试**确实会报错**，并且没改动时**不会误报**。

```bash
python tests/mutation_check.py
```

当前 9 个变异全部命中：界面 3 个（`ui_smoke.js`）、启动脚本 6 个（`bat_lint.py`）。
最后的「反向确认」会再跑一遍原始文件，确保整套测试不会无故报错。

**什么时候要跑它**：改完 `ui_smoke.js` 或 `bat_lint.py` 之后。如果你新加的断言
其实永远为真（写错了、被前面的步骤架空了），变异测试会当场把它揪出来 ——
这不是假想，M1 就是这么被发现并修掉的。

### 手动指定被测文件

两个测试都支持换文件跑，方便你手工做变异实验：

```bash
UI_HTML=/path/to/mutated_index.html node tests/ui_smoke.js
BAT_PATH=/path/to/mutated.bat        python tests/bat_lint.py
```

## 依赖

- 界面测试需要 **Node.js**（任意近年的版本）
- 脚本检查 / 变异测试需要 **Python 3**（只用标准库）
- 都不需要 `npm install`

缺了哪一样，`run_all.py` 会把那一项标成 `[SKIP]` 并返回非零退出码，不会假装通过。
